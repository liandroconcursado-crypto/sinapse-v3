# ADR 0001 — autenticação com Better Auth

- Status: aceita
- Data: 2026-09-07

## Contexto

O SINAPSE precisa derivar a identidade da sessão no servidor, persistir usuários e sessões em PostgreSQL e oferecer desenvolvimento local sem SMTP ou OAuth externo.

## Decisão

Usar Better Auth com e-mail/senha, adapter Drizzle para PostgreSQL e sessão por cookie HTTP-only. A verificação de e-mail fica desativada no desenvolvimento; assim, o usuário cria uma conta local com endereço fictício e senha sem enviar e-mail.

As rotas nunca recebem `userId` como autoridade. Elas obtêm a sessão pelos headers e constroem um `RequestContext` no servidor. Os repositórios continuam exigindo `userId` e `vaultId` explicitamente, o que torna o escopo auditável e testável.

## Consequências

- Não há dependência de serviço externo para desenvolvimento ou testes.
- As tabelas de auth entram nas migrations Drizzle versionadas.
- Produção deve fornecer `BETTER_AUTH_SECRET` e `BETTER_AUTH_URL` seguros.
- Recuperação/verificação de e-mail fica fora da primeira fatia e deve ser configurada antes de produção pública.

## Alternativas consideradas

Auth.js é maduro, mas seu provider de credenciais exige mais código próprio para cadastro, hash de senha e ciclo de sessão. OAuth-only impediria o desenvolvimento isolado exigido. Auth artesanal aumentaria a superfície de segurança sem benefício para o produto.
